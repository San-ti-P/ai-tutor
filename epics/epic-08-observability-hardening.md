# Epic 8-H: Observability Hardening

**Status:** Draft
**Extends:** [Epic 8 — Observability and Quality](./epic-08-observability.md)
**Trigger:** Trace audit of 30-integration-test run against Langfuse v4.7.1
**Delivery window:** Before Entrega 3 defense (29/06)

## Context

Epic 8 shipped Langfuse integration — traces appear in the dashboard. But a line-by-line audit of the JSONL export from 30 integration tests reveals that **only RAG spans work correctly**. LLM calls, tool calls, evaluation spans, metadata tags, session/user identity, cost tracking, and span hierarchy are all broken or absent. The v4 SDK migration was structurally correct but semantically incomplete — `create_trace` was ported to `start_observation()`, but SDK-level fields (`environment`, `userId`, `sessionId`, `traceName`) were never wired, and the CallbackHandler does not propagate through LangGraph's RunnableConfig to actual LLM invocations inside agent nodes.

This hardening epic fixes every gap found in the audit so that traces are production-grade: every execution is identifiable, every LLM call carries tokens/cost/latency, every tool invocation is visible, evaluations are auditable, and spans form a proper parent-child tree.

## Root Cause Analysis

### RCA-1: SDK-level identity fields never set
Langfuse v4 uses OpenTelemetry under the hood. `environment`, `userId`, `sessionId` are SDK-level fields, not trace `metadata`. Our `create_trace()` sets them in `metadata` dict but the SDK writes them to a different path. Fix: set via `langfuse_context.update_current_trace()` inside decorated functions, and via `Langfuse()` constructor for `environment`.

### RCA-2: CallbackHandler does not reach LLM calls
`orchestrate_chat.py` creates a `CallbackHandler` and appends it to `config["callbacks"]`. LangGraph's `ainvoke` accepts this config, but LLM calls inside agent nodes (e.g., `model.invoke(prompt)`) create their own RunnableSequence that may not inherit the parent config's callbacks. The handler is created but never actually intercepts LLM invocations. Fix: ensure config propagation through LangGraph nodes, or use `@observe()`-wrapped LLM call functions with explicit callback injection.

### RCA-3: `@observe()` decorators capture graph state, not tool logic
Tool functions in `back/src/tools/__init__.py` have `@observe()`, but the decorator captures only the function signature and return value. For tools that are LangChain `@tool`-decorated functions, the actual execution happens inside LangChain's tool executor, not at the decorator boundary. Fix: use Langfuse's built-in LangChain integration which auto-traces `@tool`-annotated functions when CallbackHandler is active, OR trace at the agent node level with explicit span creation.

### RCA-4: Test metadata fixture sets wrong fields
`_inject_test_metadata_for_integration` patches `ObservabilityManager.create_trace()` to add `metadata.environment: "test"`. But Langfuse's `environment` field is set at client construction time: `Langfuse(environment="test")`. The metadata dict is separate. Fix: set `LANGFUSE_ENVIRONMENT=test` env var in test runs, or configure the client with the correct environment at init time.

### RCA-5: Span hierarchy broken for non-LangGraph spans
LangGraph auto-generates parent-child chains for its own nodes (`parse_document` → `classify_document` → `chunk_and_embed`). But `rag_retrieve` spans (from `@observe`) and any manually-created spans don't get parented. Fix: use `langfuse_context.get_current_trace_id()` to set parent when creating child spans.

### RCA-6: LLM call metadata never populated
Even if LLM spans were created, `usageDetails`, `costDetails`, `providedModelName`, `modelParameters` are populated by the Langfuse SDK when it intercepts LangChain LLM calls. This requires the CallbackHandler to actually be in the callbacks chain during `model.invoke()`. Fix: same as RCA-2.

## Hardening Requirements

### HR-01: SDK-level trace identity
Every trace must carry:
- `environment`: from `LANGFUSE_ENVIRONMENT` env var (default `"development"`, set to `"test"` in CI/tests, `"production"` in deployed env)
- `sessionId`: execution thread ID (from LangGraph `thread_id`)
- `userId`: student ID when available, `"anonymous"` otherwise
- `traceName`: human-readable name (`"exam_generation"`, `"document_ingestion"`, `"chat"`, `"evaluation"`)
- `version`: from `pyproject.toml` version
- `service.name`: `"ai-tutor"` (OTel resource attribute)

### HR-02: LLM call spans with full detail
Every LLM invocation must emit a span with:
- `providedModelName`: actual model identifier (`gemma4:e4b-it-q8_0`, `llama-3.1-8b-instant`)
- `modelParameters`: `{temperature, max_tokens, top_p}`
- `usageDetails`: `{input: N, output: M, total: N+M}`
- `costDetails`: computed from model pricing
- `totalCost`: numeric
- `latencyMs`: from `startTime` to `endTime`
- `timeToFirstTokenMs`: for streaming calls
- `input`: first 500 chars of prompt (truncated, not full)
- `output`: first 500 chars of response (truncated, not full)

### HR-03: Tool call spans for all 8 tools
Every tool invocation (`ingest_document`, `ocr_math_extract`, `retrieve_chunks`, `generate_exam`, `generate_exercise`, `evaluate_answer`, `update_student_profile`, `get_student_summary`) must emit a span with:
- `name`: tool function name
- `input`: tool arguments (sanitized, truncated to 1KB)
- `output`: tool result or error
- `statusMessage`: `"success"` or `"error: <message>"`
- `level`: `"DEFAULT"` on success, `"ERROR"` on failure, `"WARNING"` on retry

### HR-04: Evaluation spans with auditable content
Every evaluation must emit a span with:
- `name`: `"evaluate_answer"`
- `input`: `{question, base_answer, student_answer}` (truncated)
- `output`: `{score, justification, topic, criteria_scores}`
- `level`: `"DEFAULT"` (success) or `"WARNING"` (low confidence)

### HR-05: Aggregate metrics per execution
After each graph execution, compute and trace:
- Total LLM calls, total tokens (in/out), total cost
- Tool success rate (successful / total)
- Total latency (graph start to end)
- Average evaluation score per topic
- Emitted as a dedicated `AGGREGATE` span or Langfuse score

### HR-06: Correct span hierarchy
Every trace must form a tree:
```
Root Trace (execution)
├── LangGraph root span
│   ├── parse_document (node)
│   ├── classify_document (node)
│   │   └── LLM Call (classify prompt)
│   ├── chunk_and_embed (node)
│   │   └── rag_embed_store (tool)
│   └── generate_exam (node)
│       ├── rag_retrieve (tool)
│       ├── LLM Call (generate prompt)
│       └── LLM Call (validate prompt)
├── evaluate_answer (tool)
│   └── LLM Call (evaluation prompt)
└── AGGREGATE (metrics)
```
Parent-child linking via `parentObservationId` on every non-root span.

### HR-07: Test metadata tagging
When `LANGFUSE_OBSERVE_TESTS=true`:
- `environment` = `"test"` (set at client init)
- Tags on every trace: `["test_run_id:<uuid>", "test_name:<current_test>", "source:pytest-integration"]`
- `sessionId` = test function name
- Test traces filterable separately from development/production

### HR-08: Status levels reflect reality
- `level: "ERROR"` when tool fails or LLM returns error
- `level: "WARNING"` when retry occurs or confidence below threshold
- `level: "DEFAULT"` on normal execution
- `statusMessage` populated with reason on non-DEFAULT levels

### HR-09: Prompt management integration
- `promptName` set to the prompt template identifier used (e.g., `"exam_generation_v1"`, `"evaluation_v1"`)
- Enables Langfuse prompt versioning and A/B testing

### HR-10: Deduplication of RAG embed spans
- Same document ingestion should produce exactly 1 `rag_embed_store` span
- Re-ingestion of same file with same content → new span with different `sessionId`

## Technical Design Notes

### TD-1: Langfuse v4 SDK identity model
```python
# In _client.py — set environment at client construction
_langfuse_client = Langfuse(
    public_key=settings.langfuse_public_key,
    secret_key=settings.langfuse_secret_key,
    host=settings.langfuse_host,
    environment=settings.langfuse_environment,  # NEW: from LANGFUSE_ENVIRONMENT
    release=settings.app_version,               # NEW: from pyproject.toml
)

# In @observe-decorated functions — set trace-level identity
from langfuse import observe, langfuse_context

@observe(name="exam_generation")
async def generate_exam(...):
    langfuse_context.update_current_trace(
        user_id=user_id,
        session_id=session_id,
        name="exam_generation",
        tags=["exam", f"topic:{topic}"],
    )
```

### TD-2: CallbackHandler propagation fix
The root cause of missing LLM spans: `CallbackHandler` is added to `config["callbacks"]` but LangGraph nodes that use `model.invoke()` may not inherit the callbacks. Fix by ensuring config flows through:

```python
# In orchestrate_chat.py or agent graph builder
from langfuse.langchain import CallbackHandler

langfuse_handler = CallbackHandler()

# Option A: Pass via RunnableConfig (preferred)
config = {
    "configurable": {"thread_id": session_id},
    "callbacks": [langfuse_handler],
}
result = await graph.ainvoke(state, config)

# Option B: Set global callback (fallback if A doesn't propagate)
# import langchain
# langchain.verbose = True  # enables callback propagation
```

Verify: every `model.invoke()` inside agent nodes produces an LLM span.

### TD-3: Tool tracing via LangChain integration
Langfuse's `CallbackHandler` auto-traces `@tool`-decorated LangChain tools. No separate `@observe()` needed per tool. Remove manual `@observe()` from tools and rely on CallbackHandler. For non-LangChain tools (bare async functions), wrap with explicit span:

```python
from langfuse import observe

@observe(name="rag_retrieve", as_type="span")
async def retrieve_chunks(query, collection_name, top_k, topic_filter=None):
    ...
```

### TD-4: Evaluation span structure
Replace the current `@observe()` on `evaluate_answer` that dumps full TypedDict. Instead:

```python
@observe(name="evaluate_answer", as_type="span")
async def evaluate_answer(state: EvaluateState) -> dict:
    langfuse_context.update_current_observation(
        input={
            "question": state["question"],
            "base_answer": state["base_answer"][:500],
            "student_answer": state["student_answer"][:500],
        },
    )
    result = await _do_evaluation(state)
    langfuse_context.update_current_observation(
        output={
            "score": result["score"],
            "justification": result["justification"],
            "topic": result.get("topic", "unknown"),
            "criteria_scores": result.get("criteria_scores", {}),
        },
        level="WARNING" if result["score"] < 4.0 else "DEFAULT",
    )
    return result
```

### TD-5: Aggregate metrics as Langfuse scores
```python
@observe(name="execution_metrics", as_type="span")
def emit_aggregate_metrics(trace_or_state):
    metrics = compute_aggregate_metrics(trace_or_state)
    # Emit as Langfuse scores (visible in dashboard)
    for key, value in metrics.items():
        langfuse_context.score_current_trace(
            name=key,
            value=value,
        )
```

### TD-6: Test fixture redesign
```python
@pytest.fixture(autouse=True)
def _configure_langfuse_environment(monkeypatch, langfuse_observe_tests, test_run_id, request):
    """Set Langfuse environment for test runs."""
    if langfuse_observe_tests:
        monkeypatch.setenv("LANGFUSE_ENVIRONMENT", "test")
        # Tags set via langfuse_context.update_current_trace() in conftest hooks
    # When False, mock_langfuse fixture handles mocking (no env needed)
```

### TD-7: Model pricing table
```python
# In _metrics.py or config
MODEL_PRICING = {
    "gemma4:e4b-it-q8_0": {"input": 0.0, "output": 0.0},  # local, free
    "llama-3.1-8b-instant": {"input": 0.05, "output": 0.08},  # per 1M tokens
```
